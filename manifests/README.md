# Pong Android 17 source snapshot

Captured from `/mnt/games/android17` on 2026-09-14. The maintainer reports a
successful build of this bring-up. The archive present during this audit was
`lineage-24.0-20260913-UNOFFICIAL-Pong.zip`. A new clean build of this packaged
recipe has not been performed; capture date is not a new build/test date.

Use the main [build instructions](../README.md#building). The full XML pins
1,245 project HEADs, preserves the resolved manifest's copyfile/linkfile entries,
and replaces the old device/vendor/kernel URLs with the verified public forks.
It does not contain a self-reference to the new device commit: its device revision
is the original `c9425ecc64ac12e9fd1dc040c5a119d4e23d865a`. Keep the separate
support checkout to retain this patch bundle while syncing that revision.

`patches/series.json` records each project's original HEAD, patch SHA-256 and
all affected file hashes. `apply-snapshot.py --check` performs a read-only
preflight; invocation without `--check` applies the patches after preflighting
all projects. Repeating it on the fully patched state is safe. It does not
reset repositories, stage files, create commits or resolve conflicts.

The untracked shell fragments in Dolby and ContactsProvider are excluded.
Generated build outputs, ignored files, signing keys, caches and the reconstructed
Arcsoft library are not bundled. The Arcsoft file is generated by `vendorsetup.sh`.
All tracked modifications found by the audit are included. This does not archive
the host environment or guarantee byte-identical build output.

## Verified Pong revisions

See `pong-a17-known-good.xml` for full hashes and upstream branches. All nine
public branch names were checked. Eight branch tips matched the checkout;
Dolby branch `16` had advanced to `0bae4ceb87b2d3ff0bf66c592b964c0380d1c99a`
while the working checkout remained at `d3f3d0e1e009bc1faebc9e4c4209e216777aa326`.
The snapshot intentionally retains the latter and its local patch. Tracking mode
uses the moving `16` branch and must be evaluated separately.

The kernel compiler `prebuilts/clang/host/linux-x86/clang-r563880c/bin/clang`
is tracked in the pinned AOSP prebuilts project. Kernel modules and devicetrees
are separate projects: `test` and `lineage-23.0` are intentional verified branches,
not typos to replace with `lineage-24.0`.

The [repo manifest format](https://gerrit.googlesource.com/git-repo/+/HEAD/docs/manifest-format.md)
describes project overrides and pinned revisions. A pinned manifest does not
preserve remote hosting forever; retain mirrors/LFS objects separately if archival
availability is required. Fresh downloading of all 1,245 projects has not been
validated by this audit.
